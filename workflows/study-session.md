# Study session

Read AGENTS.md and required state. Resume pending work before starting another assessment. At the first actual study session, confirm availability, set the study dates in the canonical ledger and start the diagnostic when requested. Never start teaching during an administrative reset.

A provisional 60–90 minute session can use 10–15 minutes for due recall, 25–35 for one small topic, 15–25 for scenarios, and 5–10 for a teach-back and state update. Adjust to actual availability; split sessions freely. For a short session prioritize overdue recall and one misconception.

For teaching: show the note outline; explain one section; use a concrete scenario, analogy and small diagram where helpful; pause. At topic end ask a few recall questions individually. Then present a new architecture decision, requiring the learner to name constraints, pick a service/design, and explain why the closest alternative loses. Never require perfect wording. Use initial recall to build understanding, and later exam scenarios to test application.

At every checkpoint record actual progress, not projected work. Update `memory/current_lesson_state.md`, the canonical ledger, mistakes and reviews. Schedule explicit review dates. Add up to three next actions. Keep confidence separate from correctness. Prefer high-value decisions over long lists of service trivia; audit all official task statements before readiness.

# Portable study commands
All commands work as natural language requests. A slash command is optional, not evidence that a tool registered it.

| Command | Action |
|---|---|
| /today | Resume pending work, review due items, select one evidence-based priority |
| /study-plan | Adapt canonical six-week plan and buffer from availability and diagnostic; preserve maximum deadline |
| /teach TOPIC | Follow workflows/study-session.md and canonical note outline |
| /diagnostic | Use workflows/assessment.md: 20 original questions, one at a time |
| /quiz TOPIC | Five original scenarios, one at a time with feedback |
| /review-due | Ask due retrieval prompts, update outcomes and explicit review dates |
| /flashcards TOPIC | Create a few concise retrieval/decision cards under 05-Practice; add review entries after learning |
| /compare A B | Constraints, fit, security/resilience/performance/cost, closest distractor |
| /misconceptions TOPIC | Correct a distinction, test with a new scenario, log gaps |
| /visualize TOPIC | Text diagram in chat; Mermaid in notes |
| /notes TOPIC, /summary TOPIC, /facts TOPIC | Verified note-backed reference or concise recap across the four domains |
| /new-note TOPIC, /add-service SERVICE | Update canonical notes under workflows/sources-and-notes.md |
| /review-domain N | Walk domain MOC, due recall and scenario evidence |
| /gap-analysis | Compare note and learner evidence with current official tasks/in-scope services |
| /progress | Show actual counts, open errors, overdue reviews, next steps; no invented readiness percentage |
| /fullexam | Use timed mock rules in workflows/assessment.md; no feedback before completion |
| /readiness | Use evidence and calibration limits in workflows/assessment.md |

All actions read AGENTS.md first, update only observed study state, and require no particular assistant vendor or subagent. Do not create extra progress ledgers.
